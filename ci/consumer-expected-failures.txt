# Expected consumer failures — the P0-2 allowlist.
#
# Read this file as a list of bugs, not as a list of permissions. Every entry is
# a consumer that does not build against toffy 2.0, and the job is green only
# while the consumer fails with *exactly* these errors and nothing else. New
# error → red. Consumer fixed while its entry is still here → also red, with a
# request to delete the entry: the list is the progress metric of this whole
# upgrade, and a metric nobody deletes is not a metric.
#
# Format:  <consumer@ref glob>|<substring of a normalised error line>
#
#   * The glob matches `name@ref` as passed to tools/consumer_build.sh, e.g.
#     `toffy-oatpp@main` or `toffy-oatpp@*`.
#   * The substring is matched against the *normalised* error line: the
#     compiler's `file:line:col:` prefix is stripped and whitespace collapsed,
#     so entries never name a line number and never go stale because something
#     above them moved. Copy the string from the job's "NOT on the allowlist"
#     report — that report prints exactly this form.
#   * Entries are matched case-sensitively, one per line. `#` starts a comment.
#
# Each entry must say *why* it exists and *what deletes it*. An entry without a
# reason is an entry nobody dares remove.

# toffy-oatpp @ main — the web layer binds directly to toffy's BTA sensor API,
# so it cannot be built against a toffy installed without BTA. `modules/bta` is
# added only `if (HAS_BTA)` (toffy/modules/CMakeLists.txt:9), so a BTA-less
# install ships no `toffy/bta/*.hpp` at all, and three translation units of
# toffy-oatpp include them: `src/globals.cpp:21`, and through
# `webapi/controller/btaAdapterController.hpp` the TU
# `src/webapi/controllers/btaAdapterController.cpp` plus `src/webapi/webApi.cpp`.
#
# This is not a regression and not a CI artefact: it has been true the whole
# time, and invisible because every local build had the proprietary bta SDK
# installed (measured 2026-10-30: a stage copy with `include/toffy/bta` removed
# reproduces exactly this one error; the same stage with the headers passes).
# GitHub-hosted runners cannot stage the SDK, so this is the honest ceiling of
# what CI can say about toffy-oatpp until the coupling is gated.
#
# Deleted by: **P1-13** — gate the BTA endpoints behind a feature check in
# toffy-oatpp (auto-detect `toffy/bta/bta.hpp`, exclude the controller TU and its
# two registration sites — `globals.cpp:50-53`, `webApi.cpp:129-133` — when it is
# absent), so the library builds against any toffy and the BTA endpoints appear
# only when there is a BTA to talk to. That is a product decision (does an API
# advertising a sensor it cannot reach belong in a BTA-less build?), which is why
# it is an item and not a patch in a CI commit.
toffy-oatpp@main|fatal error: toffy/bta/bta.hpp: No such file or directory
