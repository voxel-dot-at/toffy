# Expected consumer failures — the P0-2 allowlist.
#
# Read this file as a list of bugs, not as a list of permissions. Every entry is
# a consumer that does not build against toffy 2.0, and the job is green only
# while the consumer fails with *exactly* these errors and nothing else. New
# error → red. Consumer fixed while its entry is still here → also red, with a
# request to delete the entry: the list is the progress metric of this whole
# upgrade, and a metric nobody deletes is not a metric.
#
# Format:  <consumer@ref glob>|<substring of a normalised error line>
#
#   * The glob matches `name@ref` as passed to tools/consumer_build.sh, e.g.
#     `toffy-oatpp@main` or `toffy-oatpp@*`.
#   * The substring is matched against the *normalised* error line: the
#     compiler's `file:line:col:` prefix is stripped and whitespace collapsed,
#     so entries never name a line number and never go stale because something
#     above them moved. Copy the string from the job's "NOT on the allowlist"
#     report — that report prints exactly this form.
#   * What counts as an error line is defined by `error_lines()` in
#     tools/consumer_build.sh: compiler and CMake lines containing `error:`, the
#     find_package "Could not find a configuration file" gate, and — since
#     2026-11-02 — the linker's own diagnostics (`undefined reference to …`,
#     `cannot find -l…`). That last set was added because a failed link reported
#     only `collect2: error: ld returned 1 exit status`, which is the one line of a
#     link failure that says nothing; the symbol it names is now in the report, and
#     so is any new entry it produces.
#   * Entries are matched case-sensitively, one per line. `#` starts a comment.
#
# Each entry must say *why* it exists and *what deletes it*. An entry without a
# reason is an entry nobody dares remove.

# (entry deleted 2026-10-31) toffy-oatpp@main — 'fatal error: toffy/bta/bta.hpp:
# No such file or directory'  [P1-13]
#
# What it was: the web layer bound directly to toffy's BTA sensor API, so it could
# not be built against a toffy installed without BTA. `modules/bta` is added only
# `if (HAS_BTA)` (modules/CMakeLists.txt), so a BTA-less install ships no
# `toffy/bta/*.hpp`, and three translation units included them —
# `src/globals.cpp`, and through `webapi/controller/btaAdapterController.hpp` the
# controller TU and `src/webapi/webApi.cpp`. It had been true the whole time and
# was invisible because every local build had the proprietary SDK; the consumer
# job found it on a hosted runner, which cannot (measured 2026-10-30: a stage copy
# with `include/toffy/bta` removed reproduces exactly this line).
#
# What deleted it, from this repository's side: `TOFFY_WITH_BTA`, exported by
# toffyConfig.cmake and on the imported target, so the answer comes from the
# package rather than from whatever the build machine happens to have installed.
# toffy-oatpp `1c00dcc` selects the controller TU with it, exports the same answer
# as `toffy_oatpp_WITH_BTA` / `COMPONENTS BTA`, and — the product decision this
# entry was waiting on — makes the endpoints *absent* rather than 503-ing,
# because `webApi.cpp` already refused to register the controller when there was
# no bta filter in the bank.
#
# The consequence for this file is the reason it matters: with the entry gone the
# cells build, and the link-surface check — which runs only on a *successful*
# consumer build — executes on a runner for the first time. Measured against both
# stages before landing (tools/consumer_build.sh, toffy-oatpp@1c00dcc): BTA-on Debug
# = **16 symbols, exactly this baseline**; BTA-off Release = **15**, the single
# removal `toffy::FilterBank::getFiltersByType(…)` — the web layer's only caller of
# that API was the BTA capturer lookup, so a BTA-less consumer binds to strictly
# less of toffy. (`BtaWrapper`'s own symbols come from `libbta`, not `libtoffy`, so
# they were never in this surface — the guess that they would be is precisely what
# measuring instead of assuming is for.) Removals report, additions fail.
#
# And the wrinkle this entry carried settles with it: on any machine that has the
# SDK, the stale-entry check reports the entry as stale, because there the build
# passes. That was the rule working, not a bug to route around — and now both
# environments agree, which is what "deleted by P1-13" meant when it was written.
