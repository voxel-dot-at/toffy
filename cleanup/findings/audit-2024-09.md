**Note on 5 (128 vs 129).** Both figures are correct for their own pattern. The strict pattern
`(std::)?cout *<<` gives 128; the loose `std::cout` gives 29 + 100 bare = 129. The difference
is `sampleConsensus.cpp:501`, where `std::cout` sits alone on a line and the `<<` continues
below it. Use the loose pattern for a gate — it is the one that cannot miss a print — but stop
quoting the two spellings as if they were independent counts.

**Note on 12.** `filter.hpp`'s `@todo` was resolved by `P2-8` ("`@todo` in `filter.hpp`
resolved"), so the total is 20, not 21. Current distribution: `filterThread.hpp` 10,
`filterbank.hpp` 5, `controller.hpp` 4, `player.hpp` 1. `PROJECT_INFO.md`'s sentence
"`filter.hpp` and `player.hpp` carry one each" is now half wrong.

**Note on 14.** The old plan documents carried 19 in one file and 12 in another for the same
grep. The 12 in `modules/` break down as 6 `#ifdef MSVC`, 4 `#if defined(MSVC)`, 2
`#ifndef MSVC`, concentrated in `controller.cpp` (4) and `filterbank.cpp` (3). `P2-3`
deleted the seven that were wrapped round `DLLExport`/`RAWFILE`, which is where the
19 → 12 went. Tree-wide it is **16**: one more in the `libraries/sensor/` orphan and three
in `apps/main.cpp`.

**Note on 5c — the third false zero, and the largest.** Criterion 5 has always been scoped
to `modules/`, and `libraries/` was never in it. `libraries/` is not a scratch directory:
`libraries/CMakeLists.txt:4-8` puts `toffy_lib_common`, `toffy_lib_tracer`,
`toffy_lib_graphs` and `toffy_lib_skel` into `LIB_LINK`, so all 97 prints ship inside
`libtoffy.so`. 33 of them are in `thickTracer8.cpp`, 19 in `graph_utils.hpp`, 15 in
`depthSkeletonizer.cpp`. Tree-wide, library code prints **225** times, not 128 — the
scope bug hid 43 % of the remaining work on top of the 3× the bare-`cout` blind spot had
already cost. `apps/main.cpp` prints too (17 sites), but that is a CLI talking to its user
and is not counted against a library criterion.

This one is worth dwelling on: the audit that found the two `DLLExport` false zeros used
the same `modules/` scope as the check it was auditing, and so reproduced the scope bug
while reporting it. A re-verification that reuses the original scope verifies nothing.

### The false zeros, and the scope bug behind all of them

Every check in the old `DOD` verification block was scoped to `modules/`. The tree is
bigger than that:

| area | files | lines | in the DOD greps? |
|---|---|---|---|
| `modules/core` | 20 | 4,021 | yes |
| `modules/filters` | 96 | 13,606 | yes |
| `modules/bta` | 12 | 3,271 | yes |
| `libraries/` | 39 | 5,893 | **no** — and it links into `libtoffy.so` |
| `apps/` | 2 | 300 | **no** |

`libraries/sensor/include/toffy/imagesensor.hpp` is a stale duplicate of
`modules/bta/include/toffy/io/imagesensor.hpp` and still contains the exact macros `P2-3`
reports as deleted:

```cpp
18: #if defined(MSVC)
19: #define DLLExport __declspec(dllexport)
20: #define WIN true
22: #define DLLExport /**/
23: #define UNIX true
29: class DLLExport ImageSensor : public Sensor
```

It is also the 13th `MSVC` branch. `libraries/sensor/` has **no `CMakeLists.txt`**, appears in
no `add_subdirectory`, is on no include path and is not installed — it is dead, and it is the
pre-`P2-3` copy of a header that was fixed in the live location. `diff` against the live file
shows only the `P2-3` changes, which is how you can tell they are the same file at two vintages.

**This became `P3-1` — widen the verification scope, then delete the orphan.** The greps in
[`../counters.md`](../counters.md) now cover `modules/ libraries/ apps/`; deleting
`libraries/sensor/` (2 headers, nothing references them) is still open. Until it goes,
criteria 7 and 8c report green while the pattern they hunt is in the tree — the same class
of error as the `std::cout` metric that hid 100 bare `cout` sites, and as the `modules/`
scope that hides 97 prints in `libraries/`.

### N8 — small corrections to the record

All four have been applied to this document set; they are kept as the list of things a
hand-maintained record gets wrong.

- **`modules/commons/` does not exist.** The old layout table listed it as *"Small shared
  helpers (e.g. `plugins.hpp`)"*. There is no such directory; `plugins.hpp` is at
  `libraries/include/toffy/common/plugins.hpp`. The table also omitted `libraries/` (39
  files, 5,893 lines — larger than `modules/core`) and `docs/`. **Fixed in
  [`../overview.md`](../overview.md).**
- **`clang-format` is installed.** `P2-15` step 1 said *"It is **not** installed in the dev
  container today, so nobody can verify compliance locally."* `clang-format --version` →
  `Ubuntu clang-format 18.1.3`. PR 18's first step is now "pin 18.1.3 and add the CI check",
  not "find a version". Note `.clang-format` sets `Standard: Auto` and `UseTab: Never`, so the
  11 tab-bearing core files are non-conforming by the repo's own config, not by taste.
  **`P2-15` updated.**
- **`CMakeLists.txt` line citations had drifted by up to 31 lines**, because the build
  commits edited the file they cite: `enable_testing()` is `:436` not `:420`, `SOVERSION` is
  `:388` not `:372`, `CMAKE_POSITION_INDEPENDENT_CODE` is `:303` not `:293`, `HAS_BTA` is
  `:316` not `:307`, the commented-out
  `target_compile_definitions(${PROJECT_NAME} PUBLIC ${DEFINITIONS})` is `:404` not `:373`.
  All five re-checked on the current file and all five are right; `:10`, `:169`, `:207` and
  `:267` never moved. **Citations corrected throughout this set** — and the habit changed
  rather than the numbers: cite `file:symbol`, not `file:line` (rule 3 in
  [`../README.md`](../README.md)).
- **Two `<iostream>` includes survive in core** — `controller.cpp` and `filterbank.cpp` —
  and neither file uses `cout`, `cerr` or a stream any more (`filterbank.cpp`'s only match is
  a comment). `P2-3` claimed these were dropped. Harmless, but it is the include that makes
  `std::cout` cheap to reach for, which is the habit `P2-3` was trying to break. **Recorded
  against `P2-3`.**

## Whole-library warning profile

Nothing in the programme measured warnings outside core. Default configuration, full


| warning | count | where |

| `-Wmaybe-uninitialized` | 7 | `libraries/src/skeletonizers/k3m*.cpp` — `next`/`prev` pointers |
| `-Wunused-variable` | 5 | filters |
| `-Woverloaded-virtual=` | 4 | 3 core (`Mux`, see [`api.md`](api.md#n3)), 1 elsewhere |
| `-Wunused-result` | 3 | `csv_source.cpp` ×2 (`fscanf`), `objectTrack.cpp` (`system`) |
| `-Wunused-but-set-variable` | 2 | filters |
| `-Wsign-compare` | 1 | filters |

The `-Wmaybe-uninitialized` cluster is the one to look at first: seven reports in the K3M
skeletonizers, all the same `const unsigned char* next;` / `prev;` idiom, in code that
walks image borders. Either GCC is right and there is a path that reads them unset, or the
loop structure hides the initialisation. It is outside the programme's scope and untested,
so it needs a human look before it is dismissed — which is the argument for `P3-11`
(print the per-target count on every PR, fail only on core) rather than for silencing it.
